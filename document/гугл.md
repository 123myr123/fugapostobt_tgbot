# Настройка Google Cloud и Google Sheets

Для работы бота необходимо настроить доступ к Google Sheets API и Google Drive API. Есть два способа авторизации: через Service Account (служебную учётную запись) и через обычный Google-аккаунт с OAuth 2.0.

## 1. Создание проекта Google Cloud

1. Откройте [Google Cloud Console](https://console.cloud.google.com/).
2. Перейдите в [создание проекта](https://console.cloud.google.com/projectcreate).
3. Укажите название проекта и создайте его.
4. Выберите созданный проект.

Официальная инструкция: [Создание и управление проектами](https://docs.cloud.google.com/resource-manager/docs/creating-managing-projects).

## 2. Включение API

В выбранном проекте откройте [Google API Library](https://console.cloud.google.com/apis/library) и включите:

- [Google Sheets API](https://console.cloud.google.com/apis/library/sheets.googleapis.com)
- [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com)

Оба API нужны для работы с Google Sheets через `gspread`.

## 3. Способ A — Service Account

Это способ, который используется в текущем коде.

1. Откройте [Credentials](https://console.cloud.google.com/apis/credentials).
2. Создайте Service Account.
3. Создайте для него JSON-ключ и скачайте файл.
4. Настройте приложение так, чтобы `gspread` находил этот файл с учётными данными.

В `app.py` сейчас используется:

```python
gc = gspread.service_account()
```

По умолчанию `gspread` ищет JSON-файл сервисного аккаунта в стандартном каталоге конфигурации. При необходимости можно указать путь явно:

```python
gc = gspread.service_account(filename="service_account.json")
```

**Важно:** Service Account — отдельная учётная запись Google, не ваш личный аккаунт. Откройте каждую нужную таблицу и поделитесь ею с email сервисного аккаунта, предоставив необходимые права.

Документация: [gspread — Service Account](https://docs.gspread.org/en/latest/oauth2.html).

## 4. Способ B — обычный Google-аккаунт через OAuth 2.0

Этот способ позволяет авторизовать приложение от имени обычного пользователя Google. Он требует первичного входа через браузер и сохранения OAuth-учётных данных.

### Шаг 1. Настройте экран согласия OAuth

1. Откройте [Google Auth Platform](https://console.cloud.google.com/auth/overview).
2. Настройте приложение и заполните обязательные сведения.
3. Если приложение находится в режиме тестирования, добавьте свой Google-аккаунт в список тестовых пользователей.

### Шаг 2. Создайте OAuth Client ID

1. Откройте [Credentials](https://console.cloud.google.com/apis/credentials).
2. Выберите создание **OAuth client ID**.
3. В качестве типа приложения выберите **Desktop app**.
4. Создайте клиент и скачайте JSON-файл.
5. Сохраните его в корне проекта под именем `credentials.json`.

### Шаг 3. Установите зависимости

```bash
pip install "gspread[oauth]"
```

Если проект использует файл зависимостей, убедитесь, что установлен пакет `gspread` с поддержкой OAuth.

### Шаг 4. Замените строку авторизации в app.py

Найдите:

```python
gc = gspread.service_account()
```

Замените на:

```python
gc = gspread.oauth(
    credentials_filename="credentials.json",
    authorized_user_filename="authorized_user.json"
)
```

Остальной код, использующий `gc.open(...)` и `sh.worksheet(...)`, обычно менять не требуется.

### Шаг 5. Выполните первый запуск

Запустите приложение в окружении, где доступен браузер:

```bash
python app.py
```

При первом запуске откроется окно авторизации Google. Войдите в нужный аккаунт и предоставьте запрашиваемые разрешения. После успешной авторизации библиотека сохранит пользовательские учётные данные в `authorized_user.json`; при следующих запусках они будут использоваться повторно.

Первичная OAuth-авторизация может требовать интерактивного браузера, поэтому на сервере без графического окружения её лучше предварительно выполнить в подходящем окружении и безопасно перенести необходимые файлы.

### Шаг 6. Предоставьте доступ к таблицам

Откройте используемые таблицы и убедитесь, что у вошедшего Google-аккаунта есть права на чтение и редактирование. В текущем коде открываются таблицы с именами:

- `Батальоны и взводы`;
- `42_pasta`.

Проверьте также, что в них существуют листы с названиями, указанными в коде.

Официальная документация: [gspread — OAuth для обычных пользователей](https://docs.gspread.org/en/latest/oauth2.html).

## 5. Безопасность

Не добавляйте секреты и файлы авторизации в публичный GitHub. Добавьте соответствующие имена в `.gitignore`, например:

```gitignore
settings.json
credentials.json
authorized_user.json
service_account.json
token.json
app.log
```

Не публикуйте токен Telegram-бота, OAuth client secret или JSON-ключ Service Account. Ограничьте доступ к файлам учётных данных и не отправляйте их посторонним.

## 6. Проверка подключения

Если бот не может открыть таблицы, проверьте:

- включены ли Google Sheets API и Google Drive API;
- корректно ли выполнена выбранная авторизация;
- есть ли у соответствующего Google-аккаунта доступ к обеим таблицам;
- совпадают ли имена таблиц и листов с теми, что указаны в `app.py`;
- находятся ли JSON-файлы по указанным путям.
